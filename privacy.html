Privacy Notice

Draft — complete and review with an adult privacy/legal adviser before collecting real user data.

Information handled

When configured, Firebase Authentication handles account sign-in. Firestore stores profile fields, listings, favourites, reports, block records and marketplace messages. Firebase Storage stores listing and profile images. Public listings and selected profile details may be visible to visitors.

Safety and data minimisation

Use only a display name and broad city in public profiles. Do not upload identity documents, payment credentials, home addresses or private contact details. Reports are visible to the reporting account and authorised administrators. Block records are private to the account that created them.

Retention, deletion and requests

The operator must define retention periods, account deletion, listing/message deletion, data access/correction requests, backups, breach response and a real privacy contact before launch. This draft does not yet describe a fully implemented deletion workflow.

Service providers and security

Firebase services are used only after the operator configures the project and publishes security rules. No service can guarantee absolute security. Never place service-account keys or server secrets in frontend code or a public repository.

Operator details

Add the actual operator identity, contact details, jurisdiction and effective date after adult review. Do not invent these details.
